# MRPS Contracts

Общий Go-модуль на границе MRPS Cloud ⇄ Edge Node.

Контракт между ними фиксируется **кодом, а не описанием**: один и тот же тип
`capability.Profile` компилируется в обоих бинарниках, одна и та же функция
канонизации даёт одни и те же байты, один и тот же валидатор проверяет границы
настроек. Альтернатива — «описали в документе, реализовали дважды» — даёт
молчаливое расхождение, которое проявляется в поле, на чужой площадке,
за час до эфира.

```
                  ┌──────────────────┐
                  │  mrps-contracts  │
                  └────────┬─────────┘
              import       │       import
        ┌──────────────────┴──────────────────┐
        ▼                                     ▼
   MRPS Cloud                            Edge Node
   (управляющий слой)                    (площадка)
```

## Пакеты

| Пакет | Что внутри |
|---|---|
| `capability` | Capability Profile v2/v3, канонизация, подпись Ed25519, ограничения ключей, golden-вектора |
| `sessioncfg` | SessionConfig v2, границы значений (взяты из работающего Edge), значения по умолчанию |
| `health` | DTO телеметрии: снимок состояния камеры и вычисленное состояние |
| `protocol` | HMAC-подпись запросов Edge → Cloud, конверты сообщений, `SessionReport` |

## Использование

```bash
go get github.com/ramio-net/mrps-contracts@latest
```

```bash
go test ./...
```

## Почему репозиторий публичный

В контракте нет секретов: схема профиля, порядок канонизации и схема подписи
запросов. Безопасность системы держится на ключах, а не на закрытости формата —
и так и должно быть.

Публичность снимает `GOPRIVATE` и токены доступа из обоих проектов и их CI.
Это не мелочь: забытая настройка доступа к приватному модулю ломает сборку
у каждого нового разработчика, причём с невнятной ошибкой.

## Совместимость

Semver. Мажорная версия — только при несовместимом изменении.

| Изменение | Версия |
|---|---|
| Новое необязательное поле | minor |
| Новый тип сообщения | minor |
| Изменение семантики поля | **major** |
| Изменение канонизации подписи | **major**, плюс `schema_version` в профиле |
| Удаление поля | **major**, после deprecation минимум на один релиз |

**Практическое ограничение:** Edge в поле обновляется медленно — площадка может
месяцами работать на старой версии, и это нормальный режим эксплуатации, а не
запущенность. Cloud обязан поддерживать текущую и предыдущую мажорную версию
контракта одновременно.

## Golden-вектора

Оконная проверка схемы 2 без изменения подписанных байтов:
[согласованное дополнение](spec/SCHEMA2_WINDOW_VERIFICATION.md).

`capability/testdata/` содержит тройки «профиль → канонические байты → подпись».
Тест `TestGolden` прогоняется в CI этого репозитория и обоих потребителей.

Изменение канонического представления без осознанной смены версии схемы —
это разрыв контракта: площадки в поле перестанут принимать профили. Подпись либо
совпала байт в байт, либо нет; по логам такое почти не отлаживается. Поэтому
падение golden-векторов — блокирующая ошибка, а не повод обновить эталон.
